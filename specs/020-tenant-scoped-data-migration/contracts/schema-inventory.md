# Schema Inventory: Tenant-Scoped Data Migration (Roadmap 35)

This is the authoritative classification of every persisted SQLite table and event-bearing
record source touched by the daemon as of `daemon/internal/store/store.go`
`CurrentSchemaVersion = 37`. The Go inventory loader (`daemon/internal/inventory`) parses
this file. The completeness test (FR-013) FAILS when:

- a persisted table exists in SQLite that is not listed here, OR
- a registered event source exists at runtime that is not listed here, OR
- an entry here references a table or event that does not exist.

Every persisted table created by `schemaMigrations` versions 1..21 is enumerated below;
new tables added by Roadmap 35 (`tenant_migration_progress`, schema v22) are also listed.

## Format

Each row is a single inventory entry. Every column is REQUIRED.

| name | classification | tenantIdSource | migrationAction | affectedAPIs | affectedEvents | storeAccess | indexesAndUniqueness | isolationTests | rollback |

`classification` MUST be one of `tenant_owned`, `global`, `derived`.
`migrationAction` MUST be one of `add_column_backfill`, `index_rebuild`, `leave_global`,
`leave_existing` (Roadmap 34 already added the column), `derive_at_read`,
`remove_tenantless_access`, or a comma-joined combination of those.
`rollback` MUST be `backup_restore` for every entry in this delivery (per Q2).

`affectedAPIs` lists representative routes by domain prefix; the route list in
`daemon/internal/api/server.go` is authoritative. `affectedEvents` lists kebab-case
event-schema-file prefixes from `schemas/events/` (flat layout).

## Notes

- The set of persisted tables is verified by the inventory completeness test against a
  freshly-initialized SQLite test DB at the head schema version (introspecting
  `sqlite_master`). If the schema gains a table not in this list, the test fails.
- The set of event sources is verified against the registered event categories at
  daemon startup AND against the file set in `schemas/events/`. If a published category
  is not in this list, the test fails.
- Where a domain spans multiple tables (delivery, calendar, mail, computer-use,
  workflows, schedules, reminders, evaluation), each table is listed individually so
  that index and helper requirements are explicit per table.
- Roadmap 37 will edit only the `storeAccess` notes for `secret_scope_bindings`,
  `provider_auth_states`, `mcp_servers`, `mcp_server_states`, `mcp_tools`, and
  `connectors` rows when it introduces credential semantics. It MUST NOT change the
  `classification` or `tenantIdSource` of any row in this delivery.
- The R34 event `tenant-access-denied` (file
  `schemas/events/tenant-access-denied.event.schema.json`) covers tenant context
  resolution failures at the identity boundary. Roadmap 35 introduces a distinct event
  `audit-cross-tenant-access-denied` (file
  `schemas/events/audit-cross-tenant-access-denied.event.schema.json`) for cross-tenant
  data-plane denials. Both surfaces co-exist; see contracts/tenant-audit-event.json for
  the new event's payload contract.
